# Claude official-runtime probe

Verified on 2026-08-13 with Claude Code 2.1.229 on macOS.

## Runtime path

```text
SubAuth daemon -> isolated Claude Code process -> Claude subscription
```

Each request launches `claude -p` in a new temporary directory and consumes its
`stream-json` output. SubAuth disables session persistence, slash commands,
tools, MCP servers, filesystem mutation, and interactive permission prompts.
The temporary working directory is removed after the request.

SubAuth supports two official Claude Code subscription credential sources:

- a Claude.ai login managed by Claude Code and stored in macOS Keychain
- a long-lived `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token`

The setup token value is never included in protocol events or persisted by
SubAuth. The current daemon inherits it from its launch environment; Keychain
import is planned separately.

SubAuth removes `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, custom endpoint and
header overrides, cloud-provider, federation, and profile variables before
every probe and request. This matters because Claude Code gives several of
those credentials precedence over a stored subscription login. A Claude
Console/API-key login is not accepted as a ready subscription transport.

## Verified capabilities

| Capability | Result |
| --- | --- |
| Claude.ai subscription detection | Working |
| Claude Code browser login | Implemented; existing login used in live probe |
| `setup-token` detection | Fixture-tested; live token not generated |
| Text input | Working |
| Text delta streaming | Working |
| Model selection | Passed through; default model observed in live probe |
| System prompt | Working |
| Tool and MCP suppression | CLI flags applied; adversarial audit pending |
| Session continuation | Disabled in V1 |
| Image and file input | Not implemented |

The live smoke request produced `CLAUDE_OK` as two normalized text deltas and
finished with `response.completed`.

## Policy constraint

Anthropic documents OAuth subscription credentials as intended for ordinary use
of Claude Code and native Anthropic applications. It directs developers building
products or services to API-key or supported cloud-provider authentication and
does not permit third-party developers to route requests through consumer plan
credentials on behalf of users.

For that reason every Claude status and response identifies this transport as
`experimental` and includes a development/limited-preview warning. SubAuth does
not present this transport as a production-supported alternative to the Claude
API.
